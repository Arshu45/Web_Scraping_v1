## 2. Config JSON Shape — HybridPromoExtractor Interface

**Source:** `promo_scraper/hybrid_promo_extractor.py` lines 139-267

### Required fields
| Field | Type | Notes |
|-------|------|-------|
| `brand` | str | Brand name |
| `source_url` | str \| list[str] \| list[{url, category}] | Single URL, list of URLs, or list of objects |

### Optional fields (with defaults)
| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `extraction_strategy` | str | `"image"` | `"text"` \| `"screenshot"` \| `"image"` \| `"hybrid"` |
| `spider` | str | — | e.g., `"image_promo"` (stored in config, not used by extractor directly) |
| `text_selectors` | list[str] | — | CSS selectors for text extraction |
| `screenshot_selectors` | list[str] | — | CSS selectors for element screenshots |
| `banner_selectors` | list[str] | — | CSS selectors for `<img>` src URLs (image strategy) |
| `min_image_width` | int | 400 | Filter small images |
| `min_image_height` | int | 150 | Filter thin strips |
| `min_aspect_ratio` | float | 1.2 | Filter non-banner shapes |
| `exclude_url_patterns` | list[str] | `["/logo", "/icon", ...]` | URL substrings to skip |
| `request_delay_seconds` | int | 4 | Delay between Gemini calls |
| `scroll_depth` | int | 3 | Scroll iterations for lazy loading |
| `promo_keywords_pattern` | str | `DEFAULT_PROMO_PATTERN` | Override text-promo detection regex |
| `nav_retry_attempts` | int | 2 | Page.goto timeout retries |
| `cache` | object | None | Optional .get(key)/.set(key,val) cache |
| `enabled` | bool | True | Skipped by `load_targets()` if false |
| `category` | str | None | Default category for all offers from this source |

### Extraction strategies
- **`"text"`** — scrapes promo text from HTML elements directly, no Vision API
- **`"screenshot"`** — Playwright screenshots banner elements, sends to Vision API
- **`"image"`** — collects `<img>` src URLs, downloads, sends to Vision API
- **`"hybrid"`** — runs `"text"` + `"screenshot"` together (most common in existing configs)

### Return format from `extractor.run()`
```python
{
    "brand": str,
    "strategy": str,
    "images_found": int,
    "images_processed": int,
    "images_skipped": int,
    "skip_reasons": dict[str, int],
    "cache_hits": int,
    "offers_extracted": int,
    "offers_stored": 0,         # filled in by caller
    "gemini_api_calls": int,
    "image_api_calls": int,
    "text_api_calls": int,
    "estimated_cost_usd": float,
    "cost_basis": str,
    "offer_items": list[dict],  # the actual extracted offers
}
```

Each offer item in `offer_items`:
```python
{
    "title": str,        # offer text
    "brand": str,        # brand name
    "source": str,       # source identifier (e.g., "screenshot_promo", "text_promo")
    "source_url": str,   # URL it was found on
    "confidence": str,   # "high" / "medium" / "low"
    "category": str,     # assigned by categorization step (may be None initially)
}
```

## 4. Database Connection Layer

**File:** `database/connection.py`

| Export | Type | Notes |
|--------|------|-------|
| `engine` | SQLAlchemy Engine | Pool: 15 persistent + 5 overflow = 20 max |
| `SessionLocal` | sessionmaker | `autocommit=False`, `autoflush=False` |
| `get_session()` | → Session | Returns new session. Caller must commit/rollback/close. |
| `init_db()` | → None | Runs `Base.metadata.create_all()`. Alembic handles production. |

**Pattern for using sessions:**
```python
session = get_session()
try:
    # ... do work ...
    session.commit()
except Exception:
    session.rollback()
    raise
finally:
    session.close()
```

## 5. LLM Factory — `llm/factory.py`

### Architecture

```
llm/base.py      → LLMClient (abstract: .chat(messages, temperature) → str)
llm/groq_client.py → GroqClient(LLMClient)    — uses langchain_groq.ChatGroq
llm/litellm_client.py → LiteLLMClient(LLMClient) — uses litellm.completion()
llm/factory.py   → get_llm_client(), get_llm_client_with_fallback(), get_langchain_llm()
```

### Available functions

| Function | Returns | Use Case |
|----------|---------|----------|
| `get_llm_client()` | `LLMClient` | Primary provider only |
| `get_llm_client_with_fallback()` | `LLMClient` (possibly `FallbackLLMClient`) | Primary + fallback on 429 |
| `get_langchain_llm()` | LangChain `ChatGroq` or `ChatOpenAI` | For LangChain/LangGraph integration |

### `FallbackLLMClient` behavior
- On any 429 / rate_limit / quota error from primary → auto-retry on fallback
- All other errors → re-raise immediately

### Env vars
| Var | Default | Notes |
|-----|---------|-------|
| `LLM_PROVIDER` | `"groq"` | Primary: `groq` \| `litellm` |
| `LLM_FALLBACK` | `""` | Fallback provider (optional) |
| `LLM_MODEL` | `"llama-3.3-70b-versatile"` | Model name |
| `LLM_TEMPERATURE` | `"0"` | Used by `get_langchain_llm()` |
| `LLM_MAX_TOKENS` | `"5000"` | Used by `get_langchain_llm()` |
| `GROQ_API_KEY` | — | Required for Groq provider |
| `LITELLM_API_KEY` | — | Optional (falls back to GROQ_API_KEY) |
| `LITELLM_API_BASE` | — | LiteLLM gateway URL |

### Adding a new provider
1. Create `llm/<provider>_client.py` extending `LLMClient`
2. Add `elif` branch in `_build_client()` in `factory.py`
3. Set `LLM_PROVIDER=<provider>` in `.env`

> **For agent tasks:** Use `get_langchain_llm()` for LangGraph integration (returns a LangChain-compatible chat model). Use `get_llm_client_with_fallback()` for direct calls.

## 6. Master Pipeline — How Targets Are Loaded

**File:** `flows/master_pipeline.py`

```python
from scripts.run_hybrid_promo_scraper import load_targets
targets = load_targets()  # scans config/targets/*.json
```

`load_targets()` in `scripts/run_hybrid_promo_scraper.py`:
- Takes optional `target_path` for single-file mode
- Otherwise globs `config/targets/*.json`
- Filters out configs with `enabled: false`
- Returns `list[dict]`

**Prefect flow:**
- `scrape_brand_target` task: runs one brand, retries once after 15s
- `master_pipeline` flow: batches targets by `MAX_CONCURRENT_BROWSERS` (default 4), maps over each batch
- Each task calls `scrape_single_target(target)` which creates `HybridPromoExtractor(target)`, calls `.run()`, and saves offers to DB

**No DB-driven target loading exists yet.** The entire target registry is filesystem-based.

## 8. Contradictions with Implementation Plan v3

### 8a. `scraping_sources` table exists in migration history

The plan says the table doesn't exist and to extend `competitors` instead. **Partially wrong:** the initial migration *does* create `scraping_sources`, so it may exist in production databases. However, it has no SQLAlchemy model and is never used by application code. The plan's approach (extend `competitors`) is still correct — but the Alembic migration should be aware it might exist.

### 8b. Vision API in extractor uses `google.genai` SDK, not `google-generativeai`

The plan's dependency list in v3 already corrects this (`google-genai` noted as already present). No issue.

### 8c. `promotions` table has fields not in plan's awareness

The promotions table originally had `raw_text`, `promo_type`, `discount_min`, `discount_max`, `flat_value`, `min_purchase`, `coupon_code`, `user_type`, `valid_until` (from initial migration). Most were dropped in later migrations. Current model only has: `offer_title`, `category`, `source_name`, `source_url`, `extraction_confidence`, `offer_hash`, `scraped_at`, `created_at`. The plan's awareness is correct for the current state.

### 8d. `product_snapshots` table exists but plan doesn't mention it

This table (with `product_name`, `product_url`, `category_path`, `original_price`, `sale_price`, `discount_percentage`, `sku`, `is_on_sale`) exists but has no model in `database/models.py`. It appears to be a separate product-level tracking feature. Not relevant to the agent project, but worth knowing about to avoid table name conflicts.
